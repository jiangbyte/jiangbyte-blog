## 目标

不插 USB，让电脑通过 Wi-Fi 连接 Android 手机，然后使用 `adb`、Android Studio 或 Flutter 直接安装、调试和查看日志。

Android 11 及以上系统已经自带“无线调试”，不需要安装第三方 App。整个过程分为两步：

1. 首次连接时，用六位配对码让电脑和手机建立信任关系。
2. 之后通过手机的调试端口连接 `adb`。

最终连接成功后，`adb devices` 中会出现类似下面的设备：

```text
192.168.1.100:38415    device
```

这里的 IP、端口和设备序列号都只是示例，实际操作时以手机屏幕显示为准。

## 前置条件

- 手机和电脑连接在同一个局域网，通常是同一个路由器的 Wi-Fi。
- 手机系统为 Android 11 或更高版本。
- 电脑已安装 Android SDK Platform Tools，终端里能直接运行 `adb`。
- 路由器没有开启 AP 隔离或“访客网络设备隔离”。
- 手机没有开启会阻止局域网互访的安全策略。

如果使用本机的 workspace SDK，可以先加载环境：

```bash
source ~/workspace/environment/load.sh
```

确认 `adb` 可用：

```bash
command -v adb
adb version
```

正常会看到类似输出：

```text
/home/user/Android/Sdk/platform-tools/adb
Android Debug Bridge version 1.0.41
```

`adb` 版本过旧时，可能无法识别新版 Android 的无线调试 mDNS 服务。此时优先升级 Android SDK Platform Tools。

## 确认电脑和手机在同一网段

先看电脑的局域网地址：

```bash
ip -brief address
ip route
```

例如电脑地址是：

```text
wlp0s20f3    UP    192.168.1.20/24
```

手机的 IP 可以在系统 Wi-Fi 详情中查看，也可以在手机的“无线调试”页面看到。两边应处于同一网段，例如：

```text
电脑：192.168.1.20/24
手机：192.168.1.100
```

只有网段相同、路由允许设备互访，`adb` 才能直接连接。一个设备在 `192.168.1.x`、另一个在 `192.168.2.x` 时，不应先怀疑 `adb`，而要检查是否连了不同的 Wi-Fi 或路由器。

## 在手机上开启无线调试

进入：

```text
设置 → 系统 → 开发者选项 → 无线调试
```

不同厂商的路径略有差别，有些设备会放在：

```text
设置 → 更多设置 → 开发者选项 → 无线调试
```

打开“无线调试”，确认手机已连接 Wi-Fi。页面会显示“IP 地址和端口”，这个端口用于后续的 `adb connect`。

注意：无线调试页面里有两个不同的地址：

| 地址 | 用途 |
|---|---|
| “使用配对码配对设备”中的 IP 和端口 | 首次配对，执行 `adb pair` |
| 无线调试主页的“IP 地址和端口” | 配对成功后，执行 `adb connect` |

这两个端口通常不一样，不能拿配对端口直接执行 `adb connect`。

## 首次配对

在手机的“无线调试”页面点击：

```text
使用配对码配对设备
```

手机会显示：

- 配对用的 IP 地址和端口
- 六位配对码
- 配对码有效期

假设手机显示：

```text
配对地址：192.168.1.100:37123
配对码：123456
```

在电脑终端执行：

```bash
adb pair 192.168.1.100:37123
```

终端提示输入配对码时，输入手机上的六位数字：

```text
Enter pairing code: 123456
Successfully paired to 192.168.1.100:37123
```

也可以把配对码直接写在命令后面：

```bash
adb pair 192.168.1.100:37123 123456
```

配对码失效、输错或反复尝试后，关闭配对弹窗，重新点击“使用配对码配对设备”，生成一组新的地址和配对码。

配对只是建立信任关系，不代表已经连接调试。配对成功后回到无线调试主页，查看新的“IP 地址和端口”，再执行下一步。

## 连接调试端口

假设无线调试主页显示：

```text
IP 地址和端口：192.168.1.100:38415
```

执行：

```bash
adb connect 192.168.1.100:38415
```

成功时会返回：

```text
connected to 192.168.1.100:38415
```

然后检查设备：

```bash
adb devices -l
```

正常结果类似：

```text
List of devices attached
192.168.1.100:38415    device product:example model:ExamplePhone device:example
```

状态为 `device` 表示已经可以执行调试命令。

如果第一次连接时出现授权弹窗，需要在手机上点击“允许 USB 调试”。虽然这里走的是 Wi-Fi，Android 仍可能复用调试授权提示。

## 使用 mDNS 自动发现端口

新版 Android 和 Platform Tools 支持通过 mDNS 发现无线调试服务：

```bash
adb mdns services
```

可能看到：

```text
adb-example-rTJWgz    _adb-tls-connect._tcp    192.168.1.100:38415
adb-example-AbCd12    _adb-tls-pairing._tcp    192.168.1.100:37123
```

- `_adb-tls-connect._tcp` 是已经可以连接的调试服务。
- `_adb-tls-pairing._tcp` 是当前打开的配对服务。

这时可以直接使用发现到的地址：

```bash
adb connect 192.168.1.100:38415
```

mDNS 不可用时不会影响手动连接。直接从手机无线调试页面读取 IP 和端口即可。

## 在 Flutter 中使用

先确认 Flutter 能识别无线设备：

```bash
flutter devices
```

输出中应包含：

```text
ExamplePhone (mobile)    • 192.168.1.100:38415 • android-arm64 • Android 14 (API 34)
```

如果同时连接了模拟器，运行项目时应显式指定设备，避免 Flutter 让你再次选择：

```bash
flutter run -d 192.168.1.100:38415
```

调试模式和 USB 连接没有区别，可以正常使用热重载、热重启、断点和日志。构建、安装与运行 Release 包也仍然使用原来的 Flutter 命令，只是设备参数换成了无线设备 ID。

## 断开与重新连接

主动断开当前设备：

```bash
adb disconnect 192.168.1.100:38415
```

查看当前 ADB 服务状态或重启 ADB：

```bash
adb kill-server
adb start-server
adb devices -l
```

无线调试关闭、手机重启、切换 Wi-Fi 后，调试端口通常会变化。配对关系通常仍保留，但需要重新从手机读取新的调试端口：

```bash
adb mdns services
adb connect 手机IP:新的调试端口
```

如果手机已经取消配对，或者换了一台电脑，需要重新走一次“配对码 → `adb pair` → `adb connect`”流程。

## 常见问题

### `failed to connect` 或 `Connection refused`

优先检查：

1. 手机和电脑是否仍在同一 Wi-Fi。
2. 是否误用了配对端口执行 `adb connect`。
3. 手机无线调试是否在重新打开后更换了端口。
4. 路由器是否开启了 AP 隔离、访客网络隔离或设备互访限制。

重新执行：

```bash
adb mdns services
adb connect 手机IP:当前调试端口
```

### 设备显示 `offline`

先断开再连接：

```bash
adb disconnect 手机IP:端口
adb connect 手机IP:端口
```

如果仍然离线，重启 ADB，并在手机上关闭后重新打开无线调试：

```bash
adb kill-server
adb start-server
```

### 设备显示 `unauthorized`

解锁手机，查看并确认调试授权弹窗。没有弹窗时可以撤销开发者选项中的调试授权，重新开启无线调试后再配对。

### `adb mdns services` 没有结果

这不一定是故障。旧版 `adb`、Linux 的 mDNS 配置或路由器组播限制都可能导致自动发现失败。直接查看手机无线调试页面，把 IP 和调试端口组合后执行：

```bash
adb connect 手机IP:调试端口
```

### `adb server didn't ACK`

通常说明 ADB 服务没有正常启动，或者 `5037` 端口被其他进程占用。先重启服务：

```bash
adb kill-server
adb start-server
```

仍失败时检查端口占用：

```bash
ss -ltnp 'sport = :5037'
```

如果错误中包含 `could not install *smartsocket* listener: Operation not permitted`，通常是运行环境限制了本地网络监听或 socket 创建。换到普通用户终端执行，并检查容器、沙箱或系统安全策略。

## 旧版 Android 或无“无线调试”选项

Android 11 以下没有系统自带的无线调试。可以先通过 USB 建立授权连接，再临时切换为 TCP/IP：

```bash
adb devices
adb tcpip 5555
adb connect 手机IP:5555
```

连接成功后可以拔掉 USB，再确认：

```bash
adb devices -l
```

这种方式通常固定使用 `5555` 端口，安全性不如 Android 11+ 的配对式无线调试。手机重启后可能需要重新连接 USB 并执行 `adb tcpip 5555`。

## 安全建议

- 无线调试只在自己信任的局域网中使用。
- 不要把 `adb` 的 `5037`、手机的调试端口直接暴露到公网。
- 调试完成后关闭手机无线调试，并执行 `adb disconnect`。
- 不使用的电脑应及时从手机调试授权中移除。
- 配对码只用于本次配对，不要把配对码和公网调试端口一起保存或分享。
